# 信息密度

Design Standard: Leego Design UI
Standard ID: leego-design-ui
Version: 2.31.0
契约：`information-density-1`

适用于外部 Web、移动 Web、Android、iOS、Pad 与产品壳层（含小字辈）。Design Read、页面布局和审计都先读本文件，再决定说明、设置和区块顺序。外观深浅见 [壳层外观](shell-appearance.md)，不在本文件改色。

## 三条原则

### 1. 表面不放多余解释

控件、状态和结果已经说清楚的话，不再写成旁边的常驻段落、说明条或引导墙。

真正需要的解释只在用户索取时出现：

| 平台 | 唯一入口 |
|---|---|
| 指针设备 | 悬停，或键盘聚焦时可见的 tooltip |
| 触屏（移动 Web、Android、iOS、Pad） | 长按 |

tooltip / 长按内容仍至少 12px（App 用 sp），有可访问名称，不承载唯一的风险、权限、不可逆后果或错误恢复。那些信息必须留在表面上，因为用户可能不会去悬停或长按。

常驻说明墙判失败：同一视区里用段落复述按钮、字段或状态含义；用「温馨提示」「使用说明」占住首屏；把本可以放进 tooltip 的句子做成永远展开的 helper text。

### 2. 规则和默认值优先于选择

产品规则或合理默认能决定的事，不做成用户控件。

用户必须回答的问题，只出现在自然决策步骤：

- **编辑**：改的就是这一处内容或对象。
- **提交**：发出、确认、审批或不可逆动作之前。
- **导出**：范围、格式或接收方会改变产出时。

不在进入页面时铺开偏好、模式、开关或「请先选择」。没有规则、也没有安全默认、而且会改变结果的决定，才留在对应步骤；Design Read 写明推荐默认和它保护的结果。

提前设置判失败：首屏设置墙、与当前任务无关的偏好表单、在编辑/提交/导出之前就要求用户做可被默认的选择。

### 3. 先清点功能元素，再排层级

落笔前列出本页每一个功能元素（状态、动作、依据、配置、历史、必要帮助）。然后只按这个顺序排列：

1. **结论与状态**：判断结果、风险、权限、新鲜度、阻塞。
2. **主要操作**：完成本任务的主动作，以及不可拆开的直接对象。
3. **依据明细**：支撑结论的列表、计算、证据。**默认折叠。**
4. **配置与历史**：偏好、规则覆盖、旧记录、审计轨迹。优先级更低，能折叠就折叠。

没有某一层就整段省略，不留空标题。用户已经点开的折叠状态在返回同一对象时保留。折叠不能拿掉风险结论、权限、错误恢复或法律与安全信息；那些留在「结论与状态」。

明细优先判失败：依据或配置出现在结论和主要操作之前；依据明细或配置与历史默认展开，又没有「用户正在编辑/核对这一层」的任务理由。

## Design Read 必须写明

紧凑 Design Read 在原有字段之外增加这四行。缺行、或四行与下面的失败条件冲突，这次阅读不能通过：

```text
功能元素清单：本页每个功能元素，不写装饰
区块顺序：结论与状态 → 主要操作 → 依据明细（默认折叠）→ 配置与历史（默认折叠）
常驻说明：无；必要帮助只写悬停 / tooltip / 长按
用户决策：只出现在编辑 / 提交 / 导出；其余写规则或默认值
```

只审阅时对照这四行打通过、失败、未验证或不适用，不改页面。

## 审计

| 发现 | 严重级别 | 结果 |
|---|---|---|
| 常驻解释段落、说明条、引导墙复述控件或状态 | P1；把结论或主要操作挤出首屏时为 P0 | 失败 |
| 规则或默认能决定的事项做成控件，或在自然步骤之前摊开设置 | P1；挡住提交、导出或主要操作时为 P0 | 失败 |
| 未先清点就排版；依据/配置排在结论或主要操作之前；明细或历史无任务理由却默认展开 | P1 | 失败 |
| 风险、权限、不可逆后果、错误恢复只存在于 tooltip 或长按 | P0 | 失败 |

记录格式仍是：对象 → 方法（review）→ 通过 / 失败 / 未验证 / 不适用 → 证据。截图只能证明当时展开了什么，不能证明帮助是否只在悬停或长按出现；指针环境要实际悬停和聚焦，触屏要说明长按是否在本轮设备上验证过。
